## Время кадра при движении камеры (до → после)

Стенд `npm run bench:motion` (`tests/perf/motion.mjs`): настоящее окно браузера на мониторе 165 Гц, самый большой город,
покой / панорама / рывки / зум на высотах 500 м, 1, 5, 20 км. Бюджет кадра 6,06 мс; «пропуски» — кадры, не успевшие к своему vsync.

**Встроенная Intel UHD (её Chrome использует по умолчанию):**

| Высота, движение | До: p95 / p99 / макс, мс · пропуски | После: p95 / p99 / макс, мс · пропуски |
|---|---|---|
| 500 м, панорама | 12,1 / 12,3 / 18,3 · 47 из 609 | 6,2 / 12,2 / 12,2 · 29 из 629 |
| 1 км, рывки | 12,2 / 12,3 / 90,7 · 60 из 417 | 6,2 / 6,2 / 6,3 · 0 из 493 |
| 1 км, зум | 12,1 / 12,2 / 18,1 · 52 из 436 | 6,2 / 6,2 / 6,2 · 0 из 493 |
| 5 км, панорама | 12,2 / 18,2 / 24,3 · 150 из 499 | 12,0 / 12,2 / 12,2 · 38 из 621 |
| 20 км, рывки | 30,3 / 72,7 / 96,9 · 74 из 289 | 12,1 / 12,2 / 12,3 · 51 из 442 |
| 20 км, зум | 48,4 / 66,7 / 66,8 · 112 из 195 | 12,1 / 12,2 / 12,3 · 51 из 441 |

**Дискретная RTX 4050:** после исправлений ровные 165 FPS на всех высотах и при всех видах движения, p99 ≤ 6,9 мс.

Файлы: `bench/motion-before.json`, `bench/motion-after-igpu.json`, `bench/motion-after-dgpu.json`.

**Ответ на вопрос «достижимо ли 165 на ПК среднего класса».** Да, на дискретной видеокарте. На встроенной Intel UHD
этого ноутбука (16 исполнительных блоков) оставшиеся одиночные пропуски на 5–20 км при движении — предел видеокарты:
кадр занимает ~3–5 мс GPU плюс композитинг Windows. Заикания (кадры 24–97 мс) исчезли полностью; худший кадр — 12 мс.
Дальнейший резерв для слабых встроенных видеокарт: облака в 1/2 разрешения во время движения, LOD тайлов по высоте.

**Оговорка о последнем замере.** В конце сессии машина стала отдавать ровно ~130 Гц всем сборкам: и сборка из PR #11, и итоговая
в одних и тех же условиях показали p50 7,6 мс без разброса при JS 0,6 мс (`bench/motion-final.json`). Это состояние машины
(вероятно, частота встроенной видеокарты после нескольких часов прогонов), а не новые изменения: A/B в одинаковых условиях одинаков.

## Что осталось

1. Решение 2D / 3D принято — 2D; формы построек, порт и свет у входов сделаны в PR #17. Завод остаётся почти прямоугольным (его цеха и дворы занимают все клетки).
2. Полностью органичная сеть улиц (граф с кварталами любой формы) — нужна переделка наполнителя кварталов.
3. Генерация села бота идёт прямо в кадре: разовый кадр до 90 мс — вынести из кадра (воркер или по частям).
4. Метки построек на карте в одной рамке, журнал уведомлений, сверка интерфейса с работающим DroneFlames.
5. История git: в 22 старых коммитах (до этапа 6.1) автором указана личная почта из настроек git. Новые коммиты — с публичной
   noreply-почтой аккаунта. Переписать историю можно только с вашего подтверждения (это меняет все хэши и требует force push).

## Рекомендации по следующим шагам

- Выбрать 2D или 3D и сделать формы построек, затем порт и свет у входов в том же варианте.
- Перенести тяжёлые операции мира (новое село, новая зона) из главного потока в воркер.
- Для встроенных видеокарт — адаптивное качество во время движения (облака, bloom), чтобы держать 165 и на них.
